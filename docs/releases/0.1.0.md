# CrossPoint Pal 0.1.0 — Image Viewer & Low-Power Slideshow

> Draft release body for the `0.1.0` GitHub Release. Not published in this
> pass; promotion happens after review: `release/0.1.0-prep` → `main` →
> tag `0.1.0` → GitHub Release.

## Summary

First public release of CrossPoint Pal, the downstream fork of
CrossPoint Reader, based on upstream `develop` @
`5ab0f290a5d88cb54fb7e2906c6bc0ab829770f0`.
The reader core is upstream CrossPoint; this release adds two finished
feature groups — an enhanced image viewer and a low-power slideshow — and
publishes a hardware-verified binary for the XTEINK X4 Classic.

## What's new

- Enhanced BMP/PNG image viewer with persisted tone controls and render
  profiles.
- Low-power slideshow in both the image viewer and the sleep screen, driven
  by deep-sleep timer wakes.
- Firmware-visible fork identity (About screen shows the fork build), OTA
  pointed at this fork's releases, and distinctly named release assets so a
  fork binary can never be confused with an official upstream binary.

## Image viewer

- Options modal on the open image: render controls, image info, delete,
  sleep-cover assignment.
- BMP tone render controls: brightness (70–110%), gamma (0.70–1.30),
  contrast (80–130%), 4-level quantizer (Default / Legacy / Canonical).
  Defaults are an exact pass-through of the baseline pipeline.
- Persisted **viewer render profile**; a separate persisted **sleep render
  profile** is set via "Use for sleep rendering".
- Grayscale-aware BMP presentation: grayscale-capability policy picks the
  right transfer per panel/controller instead of one uniform path.

## Low-power slideshow

- **Image Viewer slideshow**: Start arms the current image; the next frames
  are shown on deep-sleep timer wakes.
- **Sleep Screen = Slideshow**: the sleep screen becomes a slideshow from
  `/.sleep` (legacy `/sleep` fallback).
- Shared interval: 1 / 5 / 10 / 30 minutes.
- **Order**: Forward (A→B→C→A), Reverse (C→B→A→C), Random (every image is
  shown once in randomized order before a new cycle begins; no immediate
  repeat across cycles). Randomized-cycle approach adapted from CrossPoint
  upstream PR #3841 by @gkaindl.
- **Low-battery cutoff**: at ≤10% charge without external power the sleep
  slideshow stops wake-looping and falls back to an ordinary static sleep
  screen (with external power, no cutoff).
- **Timeout support**: the auto-sleep timeout starts the slideshow too.
- **Grayscale-safe X4 Classic presentation (UC8279)**: every timer-wake frame
  scrubs the panel with an absolute refresh base before loading gray planes,
  so frames replace the retained physical image instead of stacking on it.

## Supported hardware

- **XTEINK X4 Classic** — hardware-tested; release binaries are published
  for this device only.
- Other upstream targets may build from source but are NOT hardware-verified
  in this fork; no release binaries for them.

## Installation

> Only for unlocked devices or devices whose recovery path you have verified
> yourself — see the USB-locked warning in the README.

**Custom .bin web flasher** (https://crosspointreader.com/#flash-tools):
select X4 Classic, choose **Custom .bin**, upload the release asset. The
fork's releases do not appear in the official release picker.

**esptool** (application image at `0x10000`, no bootloader/partition
flashing required):

```bash
pip install esptool
esptool --chip esp32s3 --port /dev/ttyACM0 \
  write-flash 0x10000 crosspoint-pal-0.1.0-x4c.bin
```

## Updating

Installed fork builds check **this repository's** releases over the air
(never upstream's). Versioning is bare semver (`0.1.0`, `0.1.1`, `0.2.0` …),
so future fork releases update normally from any released fork build.

**One-time development-build migration:** earlier development builds
self-identified with upstream-derived `1.6.5` versions and will not see
`0.1.0` as an OTA upgrade (the comparator is numeric). Flash `0.1.0` once
manually; after that OTA works as usual.

## Known limitations

- Release binaries are X4 Classic only; other targets are source-build
  options, not supported hardware.
- Slideshow battery-life figures are not yet release claims; stress-test
  observations are promising but unclaimed.
- On boards without a digital USB-detect line the external-power check falls
  back to the charger's charging state, which reads "not connected" once a
  full battery terminates charging (existing upstream platform behavior).

## Checksums

SHA256 checksums are published with the release assets (the release workflow
attaches the exact binary built from the release tag). Release-candidate
builds used for hardware UAT are distinctly named
`crosspoint-pal-0.1.0-rc-<shortsha>-x4c.bin` and are never final release
assets.
